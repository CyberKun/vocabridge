# Support domain-level SHACL shapes and multi-source validation
Labels: validation, architecture, v0.2

## Problem

v0.1 generates one closed SHACL NodeShape per dataset, targeting the whole class, with `sh:minCount 1` derived from that dataset's completeness. This works for a single dataset, but breaks when several sources describe the same class and their graphs are merged:

- each closed shape rejects properties that only another source provides
- each completeness rule fails on records from other sources

Reference fields also use `sh:nodeKind sh:IRI` rather than `sh:class`, because the referenced resources are not in the same graph during per-dataset validation.

## Proposal

Separate two kinds of constraints:

| Kind | Who owns it | Scope | Purpose |
| --- | --- | --- | --- |
| Domain shapes | Ontology / governance team, hand-written | Shared across all datasets | Define what a valid `Invoice` is anywhere |
| Mapping profile shapes | Generated by vocabridge | One dataset's graph only | Check that this mapping produced exactly what the reviewer accepted |

- `generate --shapes domain-shapes.ttl` validates the generated data against the domain shapes as well.
- New command: `vocabridge validate-graph --data a.ttl b.ttl c.ttl --shapes domain-shapes.ttl` merges graphs and validates them together, so `sh:class` checks across datasets work.
- Generated shapes are renamed and documented as a *mapping profile* and only ever validated against their own dataset's graph.
- Domain shapes are never generated from a single dataset.

## Acceptance

- The procurement example gains a hand-written `shapes/procurement-shapes.ttl` with `SupplierShape`, `PurchaseOrderShape` and `InvoiceShape`, including `sh:class` on `billedBy` and `billsOrder`.
- A test with two supplier sources that map different columns: the merged graph conforms to the domain shapes, and no false violations are reported.
- A test where an invoice references a supplier ID that does not exist fails merged validation.
- An architecture decision record in `docs/decisions/0001-domain-shapes.md` explains the choice.
